# ADR-0003: Viewer identity is a UUID AccessToken, not traditional auth

## Status
Accepted

## Context
GoatStream is a paid service — only paying Viewers should access content. The initial user base is ~30 Viewers managed manually by the Admin. Traditional auth (email + password, OAuth) adds infrastructure and onboarding friction. Fully anonymous access offers no payment gate.

## Decision
Each paying Viewer receives a UUID AccessToken generated by the Admin at payment time. The token is the Viewer's complete identity. Access is granted by presenting an active token (via URL parameter or token-entry screen). No username, no password, no sign-up form, no email verification. The Admin activates/expires tokens manually.

Token states:
- **active** — payment current, full access granted
- **expired** — payment lapsed, Paywall shown

## Reasons
1. **Zero auth infrastructure**: No password hashing, no session management, no OAuth provider, no email sending. The token is a simple DB lookup.
2. **Zero onboarding friction for the Viewer**: Open a URL, watch. Matches the "one tap to watch" UX principle.
3. **Admin control at small scale**: At ~30 Viewers, manual token management is entirely feasible. The Admin generates a UUID and shares it — that's the entire payment flow.
4. **No personal data**: No email addresses, no passwords to leak. Minimal compliance surface.

## Alternatives considered
- **Fully anonymous**: No payment gate possible. Rejected.
- **Email + password auth**: Adds password reset, email verification, session tokens, bcrypt. Not justified for 30 users.
- **OAuth (Google, etc.)**: Adds third-party dependency and forces Viewers to have an account with that provider. Rejected.

## Consequences
- AccessTokens must be treated as secrets — a leaked token gives full access until the Admin expires it. Do not log tokens. Do not embed them in client-side analytics.
- If a Viewer loses their token, the Admin generates a new one and expires the old one. No self-service recovery.
- Scaling beyond ~200 Viewers may require automated token provisioning (payment webhook → token generation). That is a V2 concern.
